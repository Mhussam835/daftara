# وسيط الطلبات بين حاسبة الآيباد ودفترة

خادم صغير جدًا مهمته الوحيدة: يستقبل الطلب من حاسبة الآيباد، وينشئ فاتورة حقيقية داخل دفترة عبر الـ API الخاص فيهم. مفتاح API لا يظهر أبدًا داخل صفحة الآيباد — يبقى محفوظًا هنا فقط على الخادم.

## 1. لماذا هذا الخادم ضروري

صفحة الآيباد صفحة عامة يقدر أي زبون يفتح أدوات المطور بالمتصفح ويشوف كودها بالكامل. لو وضعنا مفتاح دفترة داخلها مباشرة، أي شخص يقدر يسرقه وينشئ فواتير وهمية أو يوصل لبياناتكم. لهذا نحتاج هذا الخادم الوسيط: هو الوحيد اللي يعرف المفتاح، والآيباد يكلّمه هو فقط.

## 2. التجهيز

```bash
cd daftra-proxy
npm install
cp .env.example .env
```

افتح ملف `.env` واملأ:

| المتغير | من وين تجيبه |
|---|---|
| `DAFTRA_SUBDOMAIN` | الجزء قبل `.daftra.com` في رابط حسابكم (مثلاً لو الرابط `myrestaurant.daftra.com` تكتب `myrestaurant`) |
| `DAFTRA_API_KEY` | من داخل دفترة: **الإعدادات ← API ← API Keys ← Generate API key** |
| `DAFTRA_CLIENT_ID` | رقم "العميل" اللي راح تُسجَّل عليه كل طلبات الآيباد (انظر القسم التالي) |

### كيف تجيب DAFTRA_CLIENT_ID

كل فاتورة في دفترة لازم ترتبط بعميل. الأسهل إنكم تنشئون عميل واحد بالاسم "زبون آيباد" أو "Walk-in Customer" من شاشة العملاء بدفترة، وبعدين تاخذون رقم الـ ID تبعه (يظهر عادة في رابط صفحة العميل، أو عبر استدعاء `GET /clients` من الـ API). إذا كل الطلبات نقدية بدون تسجيل بيانات عميل، هذا العميل الواحد كافي لكل الطلبات.

## 3. التشغيل محليًا للتجربة

```bash
npm start
```

يشتغل افتراضيًا على `http://localhost:3000`. جرّبه بـ:

```bash
curl http://localhost:3000/health
```

لازم يرجع لك `{"ok":true,"configured":true}`.

## 4. النشر بحيث يوصله الآيباد وجهاز الكاشير

لازم الخادم يكون متاح على الإنترنت (رابط ثابت) حتى يشتغل من داخل المطعم. أسهل خيارات مجانية للبداية:

- **Render.com**: ارفع هذا المجلد على GitHub، ثم أنشئ "Web Service" جديد بـ Render واربطه بالمستودع، وأضف نفس متغيرات `.env` من إعدادات الخدمة (Environment). Render يعطيك رابط جاهز تلقائيًا مثل `https://your-app.onrender.com`.
- **Railway.app**: نفس الفكرة تقريبًا، رفع سريع من GitHub مع متغيرات بيئة.

أي منهما كافٍ لهذه المرحلة.

## 5. آخر خطوة: ربطه بحاسبة الآيباد

افتح ملف `meal-builder.html`، ابحث عن:

```js
orderApiUrl: "",
```

واستبدلها برابط الخادم بعد نشره + `/api/create-order`، مثال:

```js
orderApiUrl: "https://your-app.onrender.com/api/create-order",
```

من هذه اللحظة، كل ضغطة على "Add to Order" تنشئ فاتورة حقيقية داخل دفترة، وتظهر لدى الكاشير جاهزة للطباعة بنفس الطريقة المعتادة. إذا تركت الحقل فارغًا، الحاسبة تستمر تشتغل بوضع تجريبي محلي كما هي الآن (بدون أي اتصال فعلي).
